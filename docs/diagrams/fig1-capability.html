② 内核层 · 判定怎么发生

guard.js 分发器选关 · 取锁 · 收集各关结果 · 决定退出码（0 通过 / 1 判红 / 2 用法环境）
P1 测试识别到的测试命令退出码非 0 即红
config → package.json → vitest/jest/mocha → cargo/go/make → pytest
P2 覆盖场景数 / 断言数低于阈值即红，--strict 额外抓“声称成功却无断言”
P3 队列读 tasks/<id>/card.json，状态不是 done 即红
P4 账本哈希链断裂、回滚点提交消失即红；审计提交里有没有 Signoff trailer
P5 反空话新增文档里的占位符与无证据结论（占位符按词边界，避免误伤中文复合词）
共享底座 core.js配置解析 · 状态目录 .signoff/ · --json · 退出码约定 · 路径归一
锁.signoff/lock/ 目录 + owner.json（mkdir 原子）
陈旧判定：进程已死 或 >10 分钟；等待 SIGNOFF_LOCK_WAIT_MS（默认 8 s）
说明即代码explain p1..p5 的文本与判定逻辑写在同一份 map 里，改逻辑必须改说明

③ 数据层 · 留在仓库里的东西

config.json阈值、test_cmd、开关
installed.json安装点 sha/时间/版本 —— 审计窗口的左边界
passed{tree, mode: pass|skip, ts}，tree 变了就失效
audit.log只追加哈希链：谁、何时、什么判决、回滚点
p3.json / skips队列快照；SIGNOFF_SKIP=1 的留痕
提交信息里的 Signoff-Pass: <tree> 是“这份树真的过过闸门”的唯一凭证；--no-verify 不留痕，审计里就是 missing。

④ 外部依赖 · 只有这两样是硬要求

Node ≥ 18全部逻辑纯 JS，无构建、无原生模块
git钩子、审计窗口、祖先校验
测试运行器仓库自己的那一套；没有则退化为 python -m unittest discover 等后备
Python（仅对等测试）gates/ 参考实现，运行时永不调用
GitHub Actions可选，--no-ci 可跳过
入口五关内核数据外部
